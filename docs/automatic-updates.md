# GitHub에서 개인 계정 플러그인으로 자동 갱신

개인 계정에 저장한 Personal Cowork와 GitHub 소스는 별개의 사본입니다. 이 프로젝트의 개인용 자동 갱신은 데스크톱의 같은 대화에 붙인 예약 작업이 `main`을 주기적으로 확인하고, 기존 계정 플러그인을 Plugin Creator로 갱신하는 방식입니다. GitHub 푸시 순간 실행하는 웹훅이나 GitHub Actions 배포는 아닙니다.

워크스페이스 관리자에게는 별도의 공식 GitHub 가져오기·동기화 경로가 제공됩니다. 개인 계정용 갱신 ZIP 도구는 그 관리 기능을 설정하거나 대체하지 않습니다. [공식 GitHub 동기화](https://learn.chatgpt.com/docs/enterprise/plugin-management).

## 갱신 흐름

1. 소유자가 지정한 GitHub 저장소와 브랜치를 확인하고 한 커밋의 소스를 별도 작업 폴더에 고정합니다. 개발 중인 로컬 파일이나 다른 저장소를 수정하지 않습니다.
2. Plugin Creator로 정확한 기존 플러그인 ID의 현재 파일 목록과 내용을 읽습니다. 파일 목록 페이지와 관리 대상 텍스트를 모두 읽고 현재 릴리스 ID를 보관합니다.
3. 이미 검토한 로컬 `prepare_account_sync.py`로 스킬 파일과 버전을 비교합니다. 같은 내용은 재게시하지 않고, 변경이 있으면 기존 계정 메타데이터를 보존한 갱신 ZIP을 준비합니다.
4. `update_plugin`에 현재 릴리스 ID를 전달해 갱신합니다. 동시 변경이 발생하면 새 소스를 읽고 패키지를 다시 준비합니다. 이전 ZIP에 새 릴리스 ID만 넣어 재전송하지 않습니다.
5. 저장된 파일을 다시 읽어 스킬 내용, 버전, 기존 메타데이터와 기본 프롬프트를 대조합니다. 확인한 뒤에만 마지막 반영 커밋과 파일 지문을 원자적으로 기록합니다.

갱신 대상은 `skills/personal-cowork/`의 공통 스킬, 참고 문서, 상태 도구와 스킬 표시 자료입니다. 계정 플러그인의 이름·ID·공유 범위·기본 프롬프트와 기존 추가 파일은 유지합니다. GitHub의 스킬 파일을 자료로 읽으며, 가져온 Python·셸 코드를 실행하거나 새 서비스 접근 권한을 만들지 않습니다. 갱신 준비 도구 자체의 새 버전은 별도로 검토한 뒤 적용합니다.

## 로컬 갱신 준비 도구

Python 3.9 이상과 표준 라이브러리만 사용합니다. 다음 명령은 API를 호출하거나 계정에 게시하지 않습니다.

`fetch_sync_source.py --mirror /path/to/bare-mirror --output /path/to/fresh-snapshot`은 이 프로젝트의 공개 GitHub `main`만 가져옵니다. 원격 파일을 실행하지 않으며, 일반 파일인 manifest와 지정 스킬 경로만 고정한 커밋에서 읽습니다. 새 snapshot 폴더를 사용하고 반환된 커밋을 다음 준비 도구에 전달합니다.

```sh
python3 scripts/prepare_account_sync.py \
  --source /path/to/pinned-source \
  --current /path/to/current-account-files.json \
  --plugin-id VERIFIED_BACKEND_PLUGIN_ID \
  --commit VERIFIED_GITHUB_COMMIT_SHA \
  --state /path/to/previous-verified-state.json \
  --output /path/to/staging
```

`--current`에는 `get_plugin_files`의 완전한 파일 목록, 필요한 `contents`, `plugin` 메타데이터를 제공합니다. 첫 실행에는 `--state`를 생략합니다. 결과의 ZIP과 준비 보고서는 게시 전 자료이며, 성공한 계정 갱신의 증거가 아닙니다.

소스 버전이 계정 버전보다 높으면 소스 버전을 사용합니다. 스킬 내용이 바뀌었지만 소스 버전이 더 높지 않으면 계정 패치 버전을 증가시켜 엄격히 더 높은 버전으로 게시합니다. 따라서 같은 스킬 내용이어도 GitHub 버전과 계정 버전의 숫자가 달라질 수 있습니다. 동기화 여부는 숫자뿐 아니라 파일 내용과 마지막 반영 커밋으로 확인합니다.

## 중단과 복구

- 업로드 API는 누락 파일을 남기며 파일 삭제를 지원하지 않습니다. 이전에 관리하던 스킬 파일의 삭제가 필요하면 갱신을 중단하고 알립니다.
- 계정에서 같은 관리 대상 파일을 수동으로 수정한 경우, 이전 검증 기록과 비교해 충돌을 알립니다. 기존 추가 파일이나 프롬프트를 임의로 지우지 않습니다.
- 응답이 끊긴 업로드는 현재 원격 내용을 먼저 읽어 실제 저장 여부를 확인합니다. 같은 내용을 다시 게시해 버전만 증가시키지 않습니다.
- API·네트워크·인증 문제, 잘못된 소스 형식, 범위 밖 파일이나 심볼릭 링크가 있으면 성공으로 기록하지 않습니다. 필요한 접근을 복구한 뒤 다시 확인합니다.

## 실행 조건과 적용 범위

소유자가 설정한 기본 확인 주기는 매시간입니다. **Mac이 깨어 있고 데스크톱 앱이 실행 중이며 작업 폴더·네트워크·Plugin Creator 접근이 있어야 실행됩니다.** 컴퓨터가 꺼졌거나 잠든 동안의 즉시 갱신이나 놓친 실행의 재처리를 보장하지 않습니다. 예약 실행은 호스트의 도구·권한·사용량 제한을 따릅니다. [공식 예약 작업 안내](https://learn.chatgpt.com/docs/automations).

반영 대상은 지정한 기존 Personal Cowork 플러그인과 그 안에 포함된 스킬입니다. 다른 계정의 설치, 별도로 업로드한 독립 스킬, 다른 컴퓨터의 Codex 복제본을 함께 갱신하지 않습니다. 기존 대화가 이전 지침을 유지할 수 있으므로 갱신 후 새 Chat 또는 Work에서 플러그인을 선택해 확인합니다. 계정 소스 저장과 실제 Chat·Work 실행 검증은 구분합니다. [공식 플러그인 수정·재시험 절차](https://learn.chatgpt.com/docs/build-plugins).
